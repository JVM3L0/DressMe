# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Monorepo: `backend/` (this API), `frontend/` (SvelteKit — see the Frontend section), `docs/` (ADRs, deploy, tech debt), `CHANGELOG.md`. Root holds `docker-compose.yml` (`db`, `app` from `./backend`, `web` = nginx + static frontend from `./frontend`), the shared `.env`/`.env.example` (Dynaconf in `backend/` finds the root `.env` by walking up), `.pre-commit-config.yaml` (Ruff limited to `^backend/`) and `.github/workflows/backend.yml` (path-filtered, `working-directory: backend`). **Run all `uv` commands from `backend/`; paths below are relative to `backend/` unless they start with `docs/`, `.github/` or name a root file.**

DressMe is an async FastAPI backend (Python 3.13, managed with `uv`) backed by PostgreSQL via SQLAlchemy 2 async + asyncpg, with Alembic migrations. Code comments, log messages and GitHub issue templates are written in Portuguese.

## Commands

```bash
uv sync                              # install deps; dev+test groups are default-groups
docker compose up -d db              # (repo root) start Postgres only (localhost:5432)
uv run fastapi dev main.py           # run the API locally with reload
docker compose up --build            # (repo root) full stack at http://localhost:8080 (WEB_PORT; WEB_HOST=0.0.0.0 for LAN/phone, see README): web → app → db, gated by healthchecks; API docs at /api/docs

uv run alembic upgrade head                              # apply migrations
uv run alembic revision --autogenerate -m "<message>"    # new migration

uv run pytest                                            # all tests
uv run pytest -m "not integration"                       # unit only (no DB needed)
uv run pytest tests/unit/test_create_user.py::test_name  # single test

uv run ruff check --fix . && uv run ruff format .        # lint, sort imports, format
```

`DATABASE_URL` is **required at import time** (validated in `config/__init__.py`), so the app, Alembic and any test importing `infrastructure.persistence` fail without it. For local dev against the compose DB, put this in a `.env` (loaded by Dynaconf):

```
DATABASE_URL=postgresql+asyncpg://user_fastapi:password_fastapi@localhost:5432/app_db
```

Other settings: `MODE` (env switcher, default `development`; reads optional `settings.toml` environments) and `ECHO_SQL` (default `False`, SQL echo on the engine). Ruff is the linter, import sorter and formatter (config in `pyproject.toml`; rules E, W, F, I, UP, B, SIM). Keep code passing `ruff check` and `ruff format --check`. A `pre-commit` hook runs Ruff on commit (`uv run pre-commit install` once). Alembic runs Ruff on new migrations via `post_write_hooks`; `F401` is ignored in `alembic/versions/` so the template's `op`/`sa` imports survive in empty manual migrations. Autogenerate does not detect `server_default` changes — write those migrations by hand. `# ty:ignore` comments indicate the `ty` type checker is used.

## Architecture

Clean/hexagonal layering — dependencies point inward only:

- `domain/` — pure business core. Entities are **Pydantic models** (`domain/entities/`, with `UUIDMixin`/`LifeCycleMixin` giving `uid` and UTC `created_at`/`updated_at` via pendulum). `domain/ports/` holds `Protocol`s for external services (`PasswordHasher`, `TokenService`, `ImageProcessor`, `ImageStorage`).
- `application/` — use cases (`application/use_cases/`, one class per use case with an async `execute`) and repository `Protocol`s (`application/interfaces/`). Depends only on `domain`.
- `infrastructure/` — adapters implementing the protocols:
  - `persistence/` — SQLAlchemy ORM models (`*Orm`, separate from domain entities, with parallel `SQLUUIDMixin`/`SQLLifeCycleMixin`), `Base` with a constraint naming convention, `DatabaseSessionManager` + `get_db_session` FastAPI dependency, and the Alembic env (`script_location` is `infrastructure/persistence/alembic`; URL comes from `settings`, not `alembic.ini`).
  - `repositories/` — SQLAlchemy implementations of repository protocols; responsible for mapping domain entity ↔ ORM model and committing.
  - `auth/` — `BcryptHasher`, `JWTService` (PyJWT; HMAC only, per-algorithm min key bytes, required `sub`/`iat`/`exp`; `verify_token` returns `None` on any invalid token). `get_token_service` returns a singleton built at import so bad JWT config fails at startup.
  - `web/` — FastAPI routers and request/response schemas (`web/schemas/`, separate from domain entities).
- `main.py` — creates the `FastAPI` app and includes routers.

Wiring uses FastAPI DI in `infrastructure/web/dependencies.py`: provider functions build the concrete repository/adapters and the use case, exposed as `Annotated[..., Depends(...)]` aliases (`SessionDep`, `CreateUserUseCaseDep`, ...). Routes take the use case as a parameter and return the domain entity, which FastAPI serializes through the `response_model` schema. Tests replace providers via `app.dependency_overrides`.

`PasswordHasher` is async: `BcryptHasher` runs bcrypt in a worker thread (`anyio.to_thread`) so it doesn't block the event loop. bcrypt rejects passwords over 72 bytes, so `UserCreate` validates the byte length (not characters).

When adding a new ORM model, export it from `infrastructure/persistence/models/__init__.py` (in `__all__`) so Alembic autogenerate sees it; importing it only for side effects elsewhere gets stripped by Ruff (F401).

Business errors are plain exceptions in `domain/exceptions/`, raised by use cases and mapped to HTTP responses by handlers in `infrastructure/web/handlers.py`, registered in `main.py`. A custom `RequestValidationError` handler strips `input` from 422 responses so passwords are never echoed back.

Email and username are unique case-insensitively. Email is lowercased (domain `normalize_email`, `UserCreate`) and enforced by `CHECK ck_users_email_lowercase`. Username keeps its original casing (`normalize_username` only strips); uniqueness is by `lower(username)` in the repository query and the `uq_users_username_lower` functional unique index (declared at module level in `user_model.py`). The engine uses `hide_parameters=True` so query values never reach logs.

Tests: `tests/conftest.py` sets `MODE=testing`, selecting the `[testing]` env in `settings.toml` (placeholder `DATABASE_URL` so unit tests import without a `.env`). `tests/unit/` uses in-memory fakes (`tests/fakes.py`) and the `anyio` pytest plugin (`pytestmark = pytest.mark.anyio`). `tests/integration/` (marker `integration`) runs against real Postgres at `TEST_DATABASE_URL` (default: `DATABASE_URL` with database `<name>_test`, auto-created); each test runs in a transaction rolled back at the end (`join_transaction_mode="create_savepoint"`), and `test_migrations.py` runs Alembic upgrade/downgrade/check in a separate `*_migrations` DB. Integration tests skip if Postgres is unreachable, but fail when `CI` is set.

`SECRET_KEY` is required (custom validator message so the value never appears in errors; `[testing]` in `settings.toml` provides a test key).

Auth (ADR-0006): `POST /auth/login` sets the JWT in the `virtualfit_session` cookie (`HttpOnly`, `SameSite=Strict`, `Secure` unless `AUTH_COOKIE_SECURE=false`, which `[development]`/`[testing]` set; one week via `ACCESS_TOKEN_EXPIRE_MINUTES`); the token is never in a response body and `Authorization: Bearer` is not accepted. Protected routes take `CurrentUserDep` (`dependencies.py`: `APIKeyCookie` → `GetCurrentUserUseCase` → `NotAuthenticatedError` → 401). `AuthenticateUserUseCase` verifies a dummy bcrypt hash (`make_dummy_hash`, computed once at import) for unknown e-mails and raises the same `InvalidCredentialsError` for both cases; `CreateUserUseCase` hashes **before** the duplicate check. Keep both timing-safe. Logout only clears the cookie (no revocation, DT-10). Password policy lives in `domain/password_policy.py` (common-password list `domain/data/common_passwords.txt.gz` + no username/e-mail fragments of 4+ chars), applied in `UserCreate` with typed errors `password_common`/`password_personal` that the frontend maps; login (`LoginRequest`) deliberately skips it. Use-case tests use `FakeTokenService` (`token:<uid>`) from `tests/fakes.py`; `tests/unit/test_auth_api.py` overrides `get_user_repository`/`get_password_hasher`/`get_dummy_hash` and keeps the real `JWTService`. Signup and login are rate limited with slowapi (`infrastructure/web/rate_limit.py`, per client IP, moving window, `RATE_LIMIT_*` settings); decorated endpoints need a `request: Request` param. The limiter is disabled in the testing env; `tests/unit/test_rate_limit.py` enables it per test and calls `limiter.reset()`. Behind a proxy, uvicorn needs `FORWARDED_ALLOW_IPS` to see real client IPs. Redis storage is supported (`limits[redis]`); `tests/integration/test_rate_limit_redis.py` runs when `TEST_REDIS_URL` is set (CI has a Redis service) and checks two limiter instances share counters. Production env vars and rollout checklist: `docs/deploy.md`.

Images (ADR-0003/0007): `Photo` and `Garment` entities (`domain/entities/`, each with a `StoredImage`: generated `key`, content type, size) are owned by a user; every use case in `application/use_cases/photos.py` / `garments.py` takes `owner_id` and a foreign id is indistinguishable from a missing one (`ResourceNotFoundError` → 404). `ImageUploader` (`application/services/`) is the shared flow: size check → `ImageProcessor` → `ImageStorage.save` under `<folder>/<uuid>.<ext>` → `persist` callback, deleting the file if persisting fails; deletes remove the record first, the file second. `PillowImageProcessor` identifies JPEG/PNG by content, rejects >60 MP before decoding, applies EXIF orientation, downsizes the original to 2048 px and makes a 480 px thumbnail (same format), re-encoding both **without metadata** (GPS), in a worker thread. A `StoredImage` has one DB row but two files: `thumbnail_key` is derived from `key` (`<uuid>_thumb.<ext>`), served by `GET .../thumbnail`; always delete both (`delete_stored_image`). Grids use thumbnails, the try-on will use the full image. `LocalImageStorage` writes atomically (temp file + rename, mode 0644 so nginx can read) and its `path()` refuses keys outside `MEDIA_ROOT`. Delivery is in `infrastructure/web/media.py`: with `MEDIA_ACCEL_REDIRECT` the API answers only `X-Accel-Redirect: /_media/<key>` (nginx `internal` location on the `media` volume, read-only), otherwise `FileResponse`; `Cache-Control` is `private, immutable`. Uploads are `multipart/form-data` (`ImageFile` alias, read in chunks, 10 MB cap); route errors are typed in `infrastructure/web/responses.py`. `GarmentCategory` (`domain/enums/`) has 6 values stored as VARCHAR + CHECK (not a Postgres ENUM). Test fakes: `FakeImageProcessor`/`FakeImageStorage`/`Fake*Repository` in `tests/fakes.py`; real image bytes (with EXIF/GPS) come from `tests/images.py`; `tests/unit/test_images_api.py` overrides `get_current_user` to switch the logged-in user. Alembic: `sa.Enum(create_constraint=True)` already creates the CHECK; don't add it twice.

Outfits (ADR-0008): `Outfit` (owner, name, `garment_ids`) with tables `outfits` + `outfit_garments` (composite PK, both FKs `ON DELETE CASCADE`: deleting a garment drops it from outfits, which may end up empty). Composition rules live in `domain/outfit_rules.py` (`check_composition`: ≥1 piece, one per category except up to `MAX_ACCESSORIES`=4 accessories (`MAX_OUTFIT_GARMENTS`=8), `one_piece` excludes `top`/`bottom`; `UseCase` rejects repeated ids as `outfit_duplicate_garment`) and are applied by the use cases in `application/use_cases/outfits.py` after `GarmentRepository.list_by_ids(ids, owner)` — a garment of another user is `outfit_unknown_garment`. `InvalidOutfitError(problem)` → 422 with `{detail, code}` (a string `detail`, unlike pydantic's list). The photo is deliberately not part of an outfit. `OutfitInput` validates name (trimmed, ≤60) and 1–6 unique ids.

Config is Dynaconf only (don't add python-dotenv): `.env` + env vars override `settings.toml`. `docker-compose.yml` requires `POSTGRES_*` and `SECRET_KEY` from `.env` (template: `.env.example`) and binds ports to 127.0.0.1. In compose the API is **not published** (`expose: 8000`); only nginx reaches it, so `app` sets `FORWARDED_ALLOW_IPS=*` and `UVICORN_ROOT_PATH=/api` (for `/api/docs`). nginx (`frontend/nginx/default.conf`) strips `/api`, **overwrites** `X-Forwarded-For` with `$remote_addr` (anti-spoofing for rate limiting), serves prerendered pages via `try_files $uri $uri.html $uri/ /200.html`, caches `/_app/immutable/` for a year, and includes `nginx/security-headers.conf` in every `location` (a location-level `add_header` drops inherited ones). The Dockerfile syncs with `--no-default-groups` so dev/test tools stay out of the image.

CI (`.github/workflows/backend.yml`, runs only on changes to `backend/**`, the workflow, compose or pre-commit; concurrency group is per workflow): ruff, pytest with a Postgres service, `pip-audit` on prod deps (with documented `--ignore-vuln` entries tied to `docs/debito-tecnico.md`), and `docker build`. Actions are pinned by commit SHA.

Known tech debt lives in `docs/debito-tecnico.md`; update it when resolving or discovering items.

Architecture/scope decisions are ADRs in `docs/adr/` (accepted ADRs are never edited; supersede with a new one). The project is a **proof of concept of VirtualFit** (virtual clothing try-on) without AI (ADR-0001): manual try-on in the browser, a planned monorepo with a SvelteKit frontend (ADR-0002), and images on local disk served by nginx via `X-Accel-Redirect`, never public (ADR-0003). Check new work against these ADRs.

## Frontend

`frontend/`: SvelteKit 3 + Svelte 5 runes + TypeScript, `adapter-static` (all pages prerendered, `200.html` SPA fallback; ADR-0004). Node 24 LTS via `frontend/.node-version` (installed with fnm at `~/.local/share/fnm`; run `eval "$(~/.local/share/fnm/fnm env)"` in non-login shells). Run `npm` commands from `frontend/`:

```bash
npm run dev        # :5173; Vite proxies /api/* to the API (prefix stripped; API_PROXY_TARGET overrides)
npm run check      # svelte-check
npm run lint       # prettier --check + eslint
npm test           # vitest: "server" project (Node, *.spec.ts) + "client" project (Chromium, *.svelte.spec.ts)
npm run build
npm run e2e        # full-flow browser test against the running compose stack (BASE_URL, default :8080); also .github/workflows/e2e.yml
npm run api:sync   # backend → src/lib/api/openapi.json (scripts/export_openapi.py) → src/lib/api/schema.ts
```

- Internal imports use `#lib/...` **with explicit extensions** (`#lib/api/client.ts`); SvelteKit 3 maps `#lib/*` → `src/lib/*` with `allowImportingTsExtensions`. Use `resolve()` from `$app/paths` for internal `href`s (ESLint enforces it).
- Session (`src/lib/session.svelte.ts`): module-level `$state` read via `session.current` (`unknown` → `anonymous` | `authenticated`); `+layout.svelte` calls `loadSession()` (`GET /users/me`) once in `onMount`; the cookie is unreadable by JS, so the API is the source of truth. `/conta` redirects anonymous users and `/entrar` redirects authenticated ones with `goto(..., { replaceState: true })`. Page specs mock `$app/navigation` (`vi.hoisted` + `vi.mock`) and reset the shared session before each test.
- Photos/wardrobe (`/fotos`, `/guarda-roupa`): logic in `src/lib/photos/photos.ts`, `src/lib/wardrobe/{garments,categories}.ts` and `src/lib/media/` (`request.ts`: every call returns a `Result` — `{kind:'ok', data}` or a `FailureKind` mapped to pt-BR messages, never throws; `validation.ts`: JPEG/PNG ≤ 10 MB, mirrored from the backend). Uploads use openapi-fetch's `bodySerializer` with a `FormData` (the typed `body` is a placeholder). Pages wrap content in `RequireSession` (children receive the user) and use `LibraryPage` (intro + `HangTag` form + collection), `ImagePicker` (blob: preview, revoked on change), `SelectField`, `MediaCard` (inline delete confirmation), `MediaGrid`, `CategoryFilter`, `SiteNav` (header links). A 401 from any call goes through `loadSession()`, which flips the session to anonymous and lets `RequireSession` redirect. The lists are fetched once and filtered client-side. Images are plain `<img src="/api/photos/<id>/image">` (same origin + cookie). Svelte trims whitespace at the start/end of an element: write `Excluir <span class="visually-hidden">…</span>`, not `<span> …</span>`, or the accessible name loses its space.
- Buttons: one global system in `app.css` — `.button` (primary; 44px min height, 2px border so primary and outline are the same size), `.button.secondary` (outline, `aria-pressed` turns it primary-colored), `.button.danger`, and `.button-group` (equal-width columns, `auto-fit`, wraps to full width when narrow). Don't write per-component button CSS; use these classes (`<Icon>` goes inside, text stays in the button so the accessible name is unchanged). Tiles/chips (`OutfitSlot`, `AccessoryRow`, `CategoryFilter`, photo strip) are their own controls and keep local CSS. Component specs run without `app.css`, so sizes are only verified by `e2e/smoke.mjs` (visible `.button`s in each group: same width/height per row, ≥44px; skip hidden ones such as the closed `<dialog>`). Affordances: empty slot = category `<Icon>` + "+" badge + "Toque para escolher"; filled = swap icon; keep `cursor: pointer`, hover and `:active` feedback (disabled under `prefers-reduced-motion`). Icons live in `Icon.svelte` (class-based sizes, never inline `style`: the CSP blocks it).
- Copy without HTTPS: `canCopyImages()` is false on a plain-HTTP origin (e.g. the phone on the LAN), so `OutfitOutput` shows "Mostrar … para copiar" (full image in an `<img>`, long-press → "Copiar imagem") plus Baixar instead of Copiar; the image is cleared when the outfit/photo changes.
- Navigation (`SiteNav.svelte`): one `<nav>` that is the header links on desktop and, for a logged-in user below 48rem, a **fixed bottom tab bar** with icons (`.bar`, height `--tabbar-height`); anonymous users only get "Entrar" in the header. `+layout.svelte` reserves footer space for the bar (`.tabbar-space`, kept while the session is unknown so nothing jumps). Never rely on `position: fixed` content not covering the end of a page: keep the footer padding. `SiteNav.svelte.spec.ts` checks the bar at 390 px and the inline menu at 1280 px via `page.viewport`.
- Provador (`/provador`, ADR-0008): pure logic in `src/lib/outfit/` — `slots.ts` (`Selection` = `Partial<Record<category, Piece[]>>`, never an empty list; accessories accumulate up to `MAX_ACCESSORIES` via `choose(selection, piece, replacing?)`, `remove`, `firstIn` for single-piece categories; `choose` applies the one-piece exclusion, `orderedPieces` = body order used by the grid, the prompt and the UI, `visibleSlots`), `prompt.ts` (`buildPrompt`, deterministic, **English only**, one line per piece, sanitises names/notes), `grid.ts` (`gridFor`, `fitInCell`, no DOM), then browser-only `collage.ts` (canvas, 512 px cells, white background), `clipboard.ts` (`copyImage` takes a **Promise<Blob>** and must be called synchronously inside the click for Safari; image copy needs a secure context, else only download; `copyText` falls back to `execCommand`) and `images.ts`. Components: `OutfitSlot`, `AccessoryRow` (≤4 mini squares), `GarmentPicker` (native `<dialog>` + `showModal`; `exclude` hides pieces already used, `onremove` shows "Tirar do conjunto"), `OutfitOutput` (copy/download/share + prompt), `SavedOutfits`. Page layout = `.workspace` grid areas (`stage`, `export`, `save`, `saved`): one column on mobile with the export panel right after the stage, and from 64rem two columns with a sticky `aside.export-panel` (internal scroll if taller than the viewport) beside stage/save/saved; keep DOM order stage → export → save → saved. `OutfitOutput` shows a live collage preview built from the **thumbnails** (the copy/download still uses the full images). Don't add `position:absolute` offsets without a CSS fallback value (`var(--space-1, 0.25rem)`): component specs run without `app.css`.
- CSP (`csp.config.ts`, DT-09): `kit.csp` `mode: 'hash'` writes a `<meta>` per prerendered page; only same-origin sources, no inline scripts/styles except the hash of SvelteKit's `#svelte-announcer` `style` (`'unsafe-hashes'`), guarded by `src/csp.spec.ts` — update the hash if a SvelteKit upgrade fails it. Never add inline `<script>`/`style=` to `app.html`; `frame-ancestors` etc. are sent by nginx (`security-headers.conf`).
- API calls go through `api` (`src/lib/api/client.ts`, openapi-fetch typed by the generated `schema.ts`; same origin under `/api`, so no CORS). `fetch` is resolved per request so tests can `vi.stubGlobal('fetch', ...)`. Never edit `openapi.json`/`schema.ts` by hand; the frontend CI `contract` job fails if they're stale. `openapi-typescript` is pinned to the project's TS 6 via `overrides` (it only declares TS 5 as a peer).
- Keep logic out of components: `src/lib/login/login.ts` (validation + `submitLogin` → `LoginResult`), `src/lib/signup/validation.ts` (rules mirroring backend `UserCreate`, pt-BR messages shared with API 422 mapping in `src/lib/api/errors.ts`) and `submit.ts` (maps HTTP outcomes to a discriminated `SignupResult`).
- Design system lives in `src/app.css` tokens: Gruvbox palette (light "hard" default, dark via `prefers-color-scheme`; text pairs checked ≥ 4.5:1), Bodoni Moda (display) + Figtree (body) self-hosted via `@fontsource-variable`, 1.25 type scale. `HangTag.svelte` (yellow clothing tag) is the single signature element; components read `--field-*`/`--button-*` custom properties so the tag can restyle them. Account screens share `FormPage.svelte` (intro + tag layout), `FormAlert.svelte` (form-level `role="alert"`) and `PasswordField.svelte` (show/hide toggle). UX rules: validate on blur (not per keystroke), error replaces hint in the same grid cell (no height change, or the blur shifts the submit button and the click is lost), focus first invalid field on submit, `role="alert"` region stays in the DOM, 44px touch targets, visible focus.
- Theme: light/dark follows the system unless the user picks one (`src/lib/theme.ts`, `localStorage['theme']`, `data-theme` on `<html>`). Dark tokens in `app.css` are written twice on purpose (`@media` + `[data-theme='dark']`), because `light-dark()` would break Safari 16 (RNF05). `static/theme-init.js` (blocking `<script src>` in `src/app.html`, not inline because of the CSP) applies the saved theme before first paint; keep it in sync with `theme.ts`. `ThemeToggle` reads the theme in `onMount`, because pages are prerendered and `document` doesn't exist at build time.
- Clipboard in tests: `Object.defineProperty(navigator, 'clipboard', {value, configurable: true})` then `Reflect.deleteProperty` in `afterEach`; make the mocked `write` await each `item.getType()` like a real browser (otherwise rejected image promises never surface). `e2e/smoke.mjs` runs on `localhost` (secure context) with `grantPermissions(['clipboard-read','clipboard-write'])` and reads the real clipboard.
- `e2e/smoke.mjs` (plain `playwright`, no test runner) is the only test that sees nginx + CSP + cookies + real images together; keep it passing when changing auth, uploads, nginx or CSP, and when it misses a regression, add a step. Verify a new assertion can fail (it once passed vacuously on a 404 for a missing file). Actions in workflows are pinned by commit SHA: resolve them from the GitHub API, never from memory.
- Page specs use `src/lib/testing/api-mock.ts` (`mockApi({'GET /api/photos/': () => json(200, [])})`; routes without a mock throw). `render()` props can't carry `bind:` — pass getter/setter pairs (and `$state` for what must re-render). Several `role="alert"` regions share a page: filter with `getByRole('alert').filter({hasText})`. Unmocked `<img>` requests make the Vite proxy log `ECONNREFUSED` in test output; it's noise.
- Component tests need Chromium system libs; locally they can run in `mcr.microsoft.com/playwright:v<playwright version>-noble` (see `frontend/README.md`); run it with `--user "$(id -u):$(id -g)" -e HOME=/tmp` as in that README, or it leaves root-owned files (`.svelte-kit`, failure screenshots). Tests that call `api` must be `*.svelte.spec.ts` (browser): openapi-fetch can't build a `Request` from the relative `/api` URL in Node. Failure artifacts (`.vitest-attachments`, `__screenshots__`) are gitignored.

## Versioning

Each branch is the next product version, `<type>/<X.Y.Z>-<slug>` (ADR-0005): `feat` bumps minor, other types bump patch. Bump `backend/pyproject.toml` and `frontend/package.json` together (the API exposes the version from pyproject via `config.APP_VERSION`) and add a `CHANGELOG.md` entry.
